## Deploy Clinical Copilot to Snowflake via SPCS

Your account (`FY14573`, `AWS_AP_SOUTHEAST_7`) has two SPCS compute pools already (`SYSTEM_COMPUTE_POOL_CPU`, `SYSTEM_COMPUTE_POOL_GPU`). We'll deploy both containers (backend + frontend) as a single SPCS service with a public ingress endpoint.

### Key architectural changes for SPCS

1. **Auth**: Inside SPCS, the backend uses the Snowflake-provided OAuth token at `/snowflake/session/token` instead of a PAT. No credentials stored in the container.
2. **Account URL**: Uses `SNOWFLAKE_HOST` env var (auto-set by SPCS) instead of hardcoded account URL.
3. **Single service, two containers**: Backend (port 8000) + Frontend/nginx (port 80) run as two containers in one service. Nginx proxies API calls to `localhost:8000`.
4. **Public endpoint**: The nginx container gets a `public: true` endpoint for browser access.

### Implementation steps

**Step 1: Create image repository**
```sql
CREATE IMAGE REPOSITORY CLINICAL_COPILOT.CORE.COPILOT_IMAGES;
```

**Step 2: Modify backend auth for SPCS**
- Update `backend/app/auth.py` to read `/snowflake/session/token` when running inside SPCS (detect via `SNOWFLAKE_HOST` env var), fall back to PAT for local dev.
- Update `backend/app/config.py` to build the account URL from `SNOWFLAKE_HOST` when available.

**Step 3: Update nginx.conf for single-service networking**
- Proxy API requests to `localhost:8000` (both containers share the same network namespace in SPCS).

**Step 4: Build & push Docker images**
```bash
# Login to Snowflake image registry
docker login <org>-<account>.registry.snowflakecomputing.com
# Tag and push both images
docker tag ... <registry>/clinical_copilot/core/copilot_images/backend:latest
docker tag ... <registry>/clinical_copilot/core/copilot_images/frontend:latest
docker push ...
```

**Step 5: Create External Access Integration**
The backend needs to call the Cortex Agent REST API via the Snowflake host. Inside SPCS, this goes through Snowflake's internal network — no EAI needed for Snowflake API calls.

**Step 6: Create the SPCS service**
```sql
CREATE SERVICE CLINICAL_COPILOT.CORE.COPILOT_SERVICE
  IN COMPUTE POOL SYSTEM_COMPUTE_POOL_CPU
  FROM SPECIFICATION $$ ... $$;
```
Service spec with two containers (backend + frontend), public endpoint on port 80.

**Step 7: Verify**
- `SHOW SERVICES` to confirm RUNNING
- Access the public endpoint URL in browser
