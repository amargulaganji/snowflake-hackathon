# Sentinel360 Hackathon Upgrade — Implementation Plan

## Context

The upgrade document is ~2200 lines spanning 30+ sections. I've read every section and mapped each requirement against the existing codebase. The current app has a strong Snowflake-native foundation (Cortex Agent, 3 Search Services, Semantic View, 2 UDFs, direct SQL, 11 tables, SPCS deployment). The gaps are: no document ingestion, no inline citations, no Member Studio, no roles/audit, weak timeline, no CoCo lifecycle artifacts, and no persistent left nav.

**Key existing files that need major changes:**
- `frontend/src/App.tsx` — Root routing/state (currently sidebar+tabs, needs full nav restructure)
- `frontend/src/components/MemberDetailPanel.tsx` — Tab router (needs Overview tab + Documents tab)
- `frontend/src/components/ClinicalTimeline.tsx` — Single-line timeline (needs lane-based redesign)
- `frontend/src/components/ChatMessage.tsx` — Evidence after message (needs inline citations)
- `backend/app/routers/members.py` — Read-only (needs CRUD for Member Studio)

## Implementation Phases (8 phases)

### Phase 1: Data Model + Backend Foundation
**New Snowflake tables + backend APIs that everything else depends on**

1. Create `DOCUMENT` table (document_id, title, file_name, file_type, document_type, member_id, encounter_id, issuing_authority, category, source, jurisdiction, version, effective_date, expiration_date, source_url, page_count, checksum, ingested_at, processing_status, search_index_status)
2. Create `DOCUMENT_CHUNK` table (chunk_id, document_id, chunk_index, content_text, page_number, section, token_count)
3. Create `AI_AUDIT_LOG` table (audit_id, timestamp, user_id, user_role, member_id, action, question, tools_invoked, sources_used, risk_level, contradiction_detected, insufficient_evidence, response_preview, latency_ms)
4. Create `APP_USER` table (user_id, username, display_name, role, created_at) + seed 4 demo users (care_manager, compliance_analyst, ops_analyst, admin)
5. Add provenance columns to `POLICY_DOCUMENT` (issuing_authority, jurisdiction, version, effective_date, expiration_date, source_url, checksum)
6. Create new backend router `backend/app/routers/documents.py` — POST /documents/upload, GET /documents, GET /documents/{id}, document parsing/chunking
7. Create new backend router `backend/app/routers/studio.py` — POST /members (create), PUT /members/{id}, POST /members/{id}/medications, POST /members/{id}/diagnoses, POST /members/{id}/labs, POST /members/{id}/encounters, POST /members/{id}/claims, POST /members/{id}/notes, POST /members/generate-synthetic
8. Create new backend router `backend/app/routers/admin.py` — GET /users, GET /users/me, GET /audit-log, GET /jobs
9. Add `backend/app/services/auth_middleware.py` — role-based endpoint authorization with demo role switcher
10. Update `backend/app/main.py` — register new routers, add audit logging middleware

### Phase 2: UI Navigation Restructure
**Replace sidebar-only layout with persistent left nav + page routing**

1. Create `frontend/src/components/AppNav.tsx` — Persistent left nav with sections: Overview (Worklist), Care (Members, Member Studio), Knowledge (Documents), Operations (Jobs & Automations, Audit), Administration (Settings). Current user/role display at bottom. Role switcher for demo.
2. Add `frontend/src/types/index.ts` — new types: `AppPage`, `UserRole`, `Document`, `AuditEntry`, `JobStatus`
3. Rewrite `frontend/src/App.tsx` — Replace sidebar+main layout with AppNav+page router. Pages: worklist, members, member-detail, member-studio, documents, jobs, audit, settings, about. Member context card shown in main panel header when member selected.
4. Update `frontend/src/components/Layout.tsx` — New layout with fixed left nav + scrollable main area
5. Add global "Synthetic Data" badge to header
6. Add `ⓘ` hover tooltips next to every page title (7 tooltips with the copy from the doc)

### Phase 3: Member Overview Tab + Worklist Upgrade
**New default tab + enhanced landing page**

1. Create `frontend/src/components/MemberOverview.tsx` — Default tab when member selected. Contains: member header (name, ID, age, gender, plan, PCP, risk level, risk flags, synthetic badge), summary cards (active meds count, active dx, abnormal labs, recent encounters, claims, documents, open safety risks, compliance gaps), key risks list with evidence, recent clinical change section with "Why did risk change?" explanation, AI-generated clinical summary with citations, evidence strength indicator (Strong/Partial/Insufficient with checklist)
2. Update member tabs: Overview | Chat | Timeline | Meds | Visits | Dx | Labs | Claims | Documents. Default to Overview instead of Chat.
3. Upgrade worklist landing page: Add summary cards (High Risk Members, Risk Increased Today, Policy Gaps, New Alerts). Add filters: Risk, Name, Age, Condition, Changed Today, Plan, Has Compliance Gap. Enhanced member cards with risk change indicator and latest meaningful change.
4. Add backend endpoint `GET /members/{id}/summary` — returns computed counts and risk explanation for the Overview tab
5. Wire risk-deltas into worklist member cards (already have GET /members/risk-deltas API)

### Phase 4: Timeline Redesign
**Lane-based timeline with scroll, zoom, and event drawer**

1. Rewrite `ClinicalTimeline.tsx` — Lane-based layout with separate rows for: Encounter, Diagnosis, Medication, Abnormal Lab, Claim, Document. Scrollable viewport (min-width: 1600px). Sticky time scale axis. Non-overlapping event placement with clustering.
2. Add time range filters: 1Y, 3Y, 5Y, All
3. Add zoom control (buttons or slider to adjust time scale)
4. Add event detail drawer — clicking an event opens a right-side panel showing: title, date, source, structured values, related record/document link, evidence link
5. Keep existing type filter chips + add new event types (Claim, Document)
6. Add proper CSS for `.timeline-viewport`, `.timeline-canvas`, `.timeline-lane`, `.event-drawer`

### Phase 5: Document Ingestion + Document Viewer
**File upload, parse, chunk, index pipeline + viewer UI**

1. Create `frontend/src/components/DocumentsPage.tsx` — Document management page with category filters (All | Clinical | Policy | Regulatory | Legal), upload button, document list with status badges (Uploaded → Parsed → Chunked → Indexed → Ready | Failed), retry button for failed docs
2. Create `frontend/src/components/DocumentViewer.tsx` — Structured document viewer replacing raw text display. Shows sections (SUBJECTIVE, OBJECTIVE, ASSESSMENT, PLAN for clinical notes), AI-extracted findings highlighted, "Referenced in N answers" count, page/section metadata
3. Backend document upload: Accept file upload at POST /documents/upload, extract text (PDF via simple text extraction, TXT direct, DOCX if practical), create DOCUMENT record, chunk text into DOCUMENT_CHUNK rows, insert chunks into the Cortex Search service's source table (CLINICAL_NOTE or a new DOCUMENT_CONTENT table that feeds a Cortex Search service), update processing_status
4. Create/update Cortex Search service to include uploaded documents
5. Rename "Sources" tab to "Documents" in member view, wire to DocumentViewer
6. Update `frontend/src/components/AttachmentsTab.tsx` — merge into Documents tab or link

### Phase 6: Inline Citations + Evidence Inspector
**Clickable [1][2][3] citations in AI answers + evidence drawer**

1. Update `backend/app/services/response_parser.py` — Parse tool results into numbered citation objects. Each citation gets: index, source_type (structured/document/policy/guideline), source_name, source_id, content_preview, metadata (date, version, section, etc.)
2. Create `frontend/src/components/CitationLink.tsx` — Renders `[N]` as clickable inline link
3. Update `ChatMessage.tsx` — Post-process markdown to replace `[N]` patterns with CitationLink components. When clicked, opens Evidence Inspector drawer to that citation.
4. Create `frontend/src/components/EvidenceInspector.tsx` — Side drawer showing: source count, corroboration status, contradiction status, grouped evidence (Structured Data, Medications, Clinical Documents, Policy), each with full details. Workflow visualization (Retrieve → Safety → Policy → Validate). Does NOT expose chain-of-thought.
5. Update `AskResponse` schema to include `citations: Citation[]` array
6. Structured citation click → shows exact record (lab value, medication details)
7. Document citation click → opens DocumentViewer at relevant section with highlighted snippet
8. Policy citation click → shows policy title, authority, version, effective date, section

### Phase 7: Member Studio + Roles + Audit + Jobs
**Create synthetic members, role-based access, audit trail, job monitoring**

1. Create `frontend/src/components/MemberStudio.tsx` — Two modes: Manual (form with demographics, plan, PCP, then sub-record forms for medications, diagnoses, labs, encounters, claims, notes, documents) and Generate with CoCo (scenario generator with age range, condition checkboxes, complexity slider, include checkboxes, "Generate Synthetic Member with CoCo" button using agent for generation)
2. Create `frontend/src/components/AuditPage.tsx` — Filterable table of AI_AUDIT_LOG: timestamp, user, member, question, tools, risk, contradictions, latency
3. Create `frontend/src/components/JobsPage.tsx` — Shows Snowflake task status/history for RISK_DELTA_NIGHTLY_TASK, document processing jobs, synthetic generation jobs
4. Create `frontend/src/components/SettingsPage.tsx` — User management, role display, demo role switcher
5. Wire role-based nav visibility: Care Manager sees Worklist/Members/Chat/Clinical tabs; Compliance Analyst sees Members/Regulatory Q&A/Policy/Audit; Ops Analyst sees Worklist/Risk/Claims/Jobs; Admin sees everything
6. Backend role enforcement on endpoints (middleware checks role before allowing access)
7. Audit logging middleware — log every /ask call with user, question, tools, outcome
