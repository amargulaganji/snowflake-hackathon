### Phase 1 — Snowflake Data Foundation

**1.1 Create database and schema**
- `CREATE DATABASE CLINICAL_COPILOT`
- `CREATE SCHEMA CLINICAL_COPILOT.CORE`
- `CREATE WAREHOUSE COPILOT_WH SIZE='SMALL'`

**1.2 Structured tables (synthetic data)**
- **MEMBER** — member_id, name, dob, gender, plan_type, enrollment_date, pcp_name
- **ENCOUNTER** — encounter_id, member_id FK, encounter_date, type (inpatient/outpatient/ER), provider_name, facility, primary_diagnosis_code, notes_summary
- **MEDICATION** — medication_id, member_id FK, drug_name, ndc_code, start_date, end_date, dosage, prescriber, is_active
- **DIAGNOSIS** — diagnosis_id, member_id FK, icd10_code, description, diagnosed_date, status (active/resolved), diagnosing_provider
- **LAB_RESULT** — lab_id, member_id FK, test_name, loinc_code, result_value, unit, reference_range, result_date, abnormal_flag

**1.3 Unstructured tables**
- **CLINICAL_NOTE** — note_id, member_id, encounter_id, note_date, note_type (progress/discharge/consult), author, content_text (the full clinical note)
- **POLICY_DOCUMENT** — doc_id, policy_name, category (formulary/prior-auth/step-therapy/coverage), effective_date, content_text
- **DRUG_INTERACTION_GUIDELINE** — guideline_id, drug_pair, severity (minor/moderate/major/contraindicated), description, source, content_text

**1.4 Synthetic data generation**
- SQL script generating ~50 synthetic members with realistic clinical profiles
- ~200 encounters, ~300 medications, ~400 diagnoses, ~500 lab results
- ~100 clinical notes with realistic narrative text
- ~30 policy documents, ~50 drug interaction guidelines

### Phase 2 — Snowflake AI Layer

**2.1 Semantic View (for Cortex Analyst)**
- Create `CLINICAL_COPILOT.CORE.CLINICAL_SEMANTIC_VIEW` via YAML → `SYSTEM$CREATE_SEMANTIC_VIEW_FROM_YAML`
- Logical tables: Members, Encounters, Medications, Diagnoses, LabResults
- Dimensions: member name, gender, drug name, ICD-10 code, encounter type, etc.
- Facts: dosage, result_value, abnormal_flag
- Metrics: active_medication_count, polypharmacy_count (≥5 active meds), abnormal_lab_count, encounter_frequency
- Relationships: all FK joins defined
- Verified queries: 5-10 common questions like "What medications is member X on?", "Show lab results for member Y"

**2.2 Cortex Search Services (3 services)**

1. **CLINICAL_NOTES_SEARCH** — `ON content_text`, ATTRIBUTES: member_id, note_type, note_date
2. **POLICY_DOCS_SEARCH** — `ON content_text`, ATTRIBUTES: category, policy_name
3. **DRUG_INTERACTION_SEARCH** — `ON content_text`, ATTRIBUTES: drug_pair, severity

Each with `TARGET_LAG = '1 hour'`, warehouse = `COPILOT_WH`.

**2.3 Custom UDFs (generic tools for the Agent)**

1. **SCORE_POLYPHARMACY_RISK(member_id)** — Returns JSON with risk_level (low/moderate/high), active_med_count, flagged_interactions[], reasoning
2. **CHECK_POLICY_COMPLIANCE(member_id, drug_name)** — Returns JSON with compliant (bool), policy_name, requirements[], gaps[]

Both are SQL UDFs that query the structured tables and return VARIANT.

**2.4 Cortex Agent**
- Create `CLINICAL_COPILOT.CORE.CLINICAL_COPILOT_AGENT` via SQL DDL (`CREATE AGENT`)
- Tools:
  - `cortex_analyst_text_to_sql` → linked to the semantic view
  - `clinical_notes_search` (cortex_search) → linked to CLINICAL_NOTES_SEARCH service
  - `policy_docs_search` (cortex_search) → linked to POLICY_DOCS_SEARCH service
  - `drug_interaction_search` (cortex_search) → linked to DRUG_INTERACTION_SEARCH service
  - `score_polypharmacy_risk` (generic/function) → linked to UDF
  - `check_policy_compliance` (generic/function) → linked to UDF
- Instructions:
  - Response: "Provide evidence-backed answers. Always cite sources. Include risk badges. If evidence is insufficient, say so explicitly rather than guessing. When structured data contradicts clinical notes, flag a contradiction."
  - Orchestration: "For medication/risk questions, use Analyst first for structured data, then search clinical notes for corroboration. For policy questions, search policy docs. Always run drug interaction check for medication queries."
- Analytical search enabled for corpus-wide note analysis

### Phase 3 — FastAPI Backend

**3.1 Project structure**
```
backend/
├── app/
│   ├── main.py              # FastAPI app, CORS, lifespan
│   ├── config.py            # Settings (Snowflake account URL, etc.)
│   ├── auth.py              # PAT/keypair token generation for Cortex API
│   ├── routers/
│   │   ├── members.py       # GET /api/members/search?q=...
│   │   └── agent.py         # POST /api/agent/query, GET /api/agent/stream
│   ├── services/
│   │   ├── snowflake_client.py  # Cortex Agent REST API wrapper
│   │   └── response_parser.py   # Parse agent SSE into structured response
│   └── models/
│       └── schemas.py       # Pydantic models for request/response
├── requirements.txt
└── .env.example
```

**3.2 Key endpoints**
- `GET /api/members/search?q={query}` — Calls Cortex Agent with a member-lookup query, returns member list
- `POST /api/agent/query` — Body: `{member_id, question}`. Calls Cortex Agent REST API (`POST /api/v2/databases/.../agents/{name}:run`) with `stream: false`. Parses response into structured JSON with `answer`, `evidence_chain[]`, `risk_level`, `contradiction_detected`
- `GET /api/agent/stream?member_id=X&question=Y` — SSE streaming variant using `stream: true`

**3.3 Response parser**
- Extract text blocks → main answer
- Extract tool-use/tool-result blocks → evidence chain items (which tool, what was found)
- Detect risk keywords → risk_level badge
- Detect contradictions between analyst results and search results → contradiction_detected flag

```
└── tsconfig.json
```

**4.2 Zerodha Kite-inspired theme**
- Dark background (#1b1b2f or #131722), white/light-gray text
- Green accent (#00d09c) for positive/low-risk, red (#ff5722) for high-risk, amber (#ffa726) for moderate
- Monospace data fonts, compact tables, minimal chrome
- Dense information layout — no wasted whitespace

**4.3 Core UX flow**
1. Member search bar at top — type-ahead with debounce
2. Select member → profile card appears (name, DOB, plan, PCP)
3. Chat panel below — ask natural language questions
4. Each response shows:
   - AI-generated answer text
   - Risk badge (low/moderate/high) color-coded
   - Contradiction banner (if structured ≠ notes)
   - Expandable evidence chain: each evidence item shows source (Analyst SQL result / Clinical Note snippet / Policy Doc / Drug Interaction), with the relevant excerpt highlighted
5. "Insufficient evidence" state — the agent's decline-to-answer is displayed clearly
