### A2. Corrected Snowflake Assumptions

| Assumption | Reality |
|---|---|
| Row Access Policies on source tables protect Cortex Search results | **Wrong.** Cortex Search indexes data at creation time. RAPs are not enforced at search query time. Must use explicit `filter` parameter. |
| Snowflake REST API `/v2/statements` supports bind parameters | **Partially.** The API supports `bindings` in the payload. Current `sql_client.py` doesn't use them. Will add bindings support. |
| `ACCOUNTADMIN` is acceptable for app runtime | **Wrong.** Violates least-privilege. SPCS service should use a dedicated app role. |
| Streamlit-in-Snowflake respects caller's identity for data access | **Wrong by default.** SiS runs with owner's rights unless restricted caller's rights is explicitly configured. Sensitive per-user audit data must not be exposed. |
| One Snowflake user with multiple secondary roles is sufficient for testing | **Wrong for auth testing.** Each persona needs its own Snowflake user to test RAP + role resolution in isolation. |

### A3. Final Schema / Versioning Design

**Approach:** Current-row-in-main-table + separate `*_VERSION` tables.

**New columns on existing clinical tables** (ENCOUNTER, MEDICATION, DIAGNOSIS, LAB_RESULT, CLINICAL_NOTE):
- `RECORD_STATUS VARCHAR DEFAULT 'FINAL'` — lifecycle state
- `VERSION_NUMBER INT DEFAULT 1`
- `UPDATED_BY VARCHAR`
- `UPDATED_AT TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP()`

**New `*_VERSION` tables** (one per clinical entity):
- All columns from the parent table
- `VERSION_ID VARCHAR NOT NULL` (PK)
- `CHANGE_REASON VARCHAR`
- `CHANGED_BY VARCHAR`
- `CHANGED_AT TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP()`

**New `AUDIT.CLINICAL_AUDIT_LOG`** table in new `AUDIT` schema:
- `AUDIT_ID, TABLE_NAME, RECORD_ID, ACTION, OLD_RECORD_STATUS, NEW_RECORD_STATUS, CHANGED_BY, CHANGE_REASON, CHANGED_AT, DETAILS`

### A4. Final Role Model

| Role | Type | Capabilities |
|---|---|---|
| `PHYSICIAN_ROLE` (NEW) | Persona | Clinical read + write on assigned members. Can finalize, amend records. |
| `CARE_MANAGER_ROLE` | Persona (existing) | Clinical read + write, documents, member studio |
| `COMPLIANCE_ANALYST_ROLE` | Persona (existing) | Clinical read, claims, policy, audit |
| `OPERATIONS_ANALYST_ROLE` | Persona (existing) | Member read, claims, jobs (read-only) |
| `SNOWCARE_ADMIN_ROLE` | System admin (existing) | System config, user management. NOT routine clinical author. |
| `SNOWCARE_APP_ROLE` (NEW) | Service role | Least-privilege role for backend service operations |

### A5. Final Search Authorization Approach

1. Rebuild `CLINICAL_NOTES_SEARCH` with `MEMBER_ID` and `RECORD_STATUS` as attribute columns
2. Rebuild `DOCUMENT_SEARCH` — join chunks with documents to include `MEMBER_ID` as attribute
3. `POLICY_DOCS_SEARCH` and `DRUG_INTERACTION_SEARCH` are global (no member scoping needed) — add `ACCESS_SCOPE='GLOBAL'` attribute for clarity
4. Backend `/ask` endpoint: before calling Cortex Agent, query `USER_MEMBER_ACCESS` for the calling user's authorized member list, inject as `filter: {"@eq": {"MEMBER_ID": "Mxxx"}}` (or `@in` for multiple) on every search tool invocation
5. Agent tool definitions updated to pass filters

### A6. Streamlit Security Decision

- Streamlit dashboard continues to show **aggregate population health metrics only** (risk distribution, medication analytics, encounter trends)
- **No per-user audit data** in Streamlit
- **No member-level PII detail** beyond what the Snowflake session role grants
- Detailed audit, per-member clinical data, and user-specific views remain in the React app where caller-rights auth is enforced
